# Is it done, and is it right?

Run this check yourself before you hand in any assignment. It follows the class contract, so passing it here means no surprises in class.

A script can answer a few of these lines for you: run `node checks/check.mjs`. The rest need you.

You can ask your AI tool to go through it with you. It can find where to look and what is missing. It cannot tick a box for you: each line is something **you** have seen or can say.

## 1. It runs

- [ ] Someone else can open it from a fresh copy using only the README
- [ ] The core thing works: the one moment this assignment is about
- [ ] I tried an ordinary case **and** one at the edge (empty, slow, wrong, unexpected), and I know what happens
- [ ] Anything that is a stand-in is labelled: scripted reply, simulated hardware, sample data, temporary picture

## 2. I checked it, and I did not only run it

- [ ] For each change I kept, I said what should happen and what should stay the same, **before** I made it
- [ ] I looked at the result and compared it with what I expected
- [ ] One person has tried it, with their agreement, and I wrote down what they did and said (when the assignment asks for it)

## 3. I can explain it

- [ ] I can walk through the whole path: what comes in, what handles it, what changes, what goes out
- [ ] I can say where each part runs: browser, my computer, a server, a provider, a device
- [ ] I can explain one piece of code that matters, whoever wrote it, and say what would happen if one thing changed
- [ ] There is nothing in what I am presenting that I would have to ask AI to explain

## 4. The record shows how it was made

- [ ] The project has its own folder and a Git history: commits as I went, each saying what changed and why
- [ ] The README says what it is, who it is for and how to run it
- [ ] My process record is up to date: what I tried, what I saw, what I decided and why
- [ ] It says what AI did and what I did: the tool, the prompts that mattered, what I kept, changed or threw away
- [ ] For any generated asset, I can explain its inputs, tool/model when known, steps, my edits and checks; unknown details are marked

## 5. People, credit and safety

- [ ] No key or password is in any file Git tracks
- [ ] No one else's personal information, face or voice went to an AI service without their agreement
- [ ] Every source, asset and library is credited, and every source is one I actually opened
- [ ] It can be used without the one device or sense I assumed: there is a labelled sample or a described alternative

If a line cannot be ticked, write why in your process record and bring it to class. A clear account of what is not finished is part of the work; a ticked box that is not true is not.

## What I always do, and what AI can do

A way to decide before you ask for help. Adjust it for your project and keep it where your AI tool can read it.

| I always do this myself | AI can do this, and I check it | Either, if I say which in my record |
| --- | --- | --- |
| Decide what the project is for and who it is for | Explain code, an error or a concept | Write a first draft of code for one small change |
| Choose between alternatives, and say why | Suggest alternatives with trade-offs | Draft the README or a diagram from my notes |
| Say what a change should do before it is made | Find where in the project a behavior comes from | Make placeholder pictures, sound or data, labelled as such |
| Look at the result and decide to keep it or not | Propose one small change and a way to check it | Review my work against this page |
| Explain the work in class | Point out what I have not tested | |
| Talk to the person who tries it | | |

Two things AI never does in this class: decide for you, and act where you are not watching. It works inside your project folder, on a branch, one change at a time, and it waits for your choice before editing.
